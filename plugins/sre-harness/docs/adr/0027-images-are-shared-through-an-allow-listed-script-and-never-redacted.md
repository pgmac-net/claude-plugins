# Images are shared through an allow-listed script, checked by content, never redacted, and kept with the incident

During an incident the agent is asked for graphs: load from sar, a Grafana panel, the nagiosgraph history of the check that alerted. It could make them (with approval), but nothing it wrote ever left the machine as anything but text, so a responder in Slack never saw one (homelabia#289). This records how images now reach chat, and how the agent draws them.

**Slack's side is fixed by the free plan.** The legacy `files.upload` method is retired; the only upload is `files.getUploadURLExternal` then `files.completeUploadExternal` (slack-sdk's `files_upload_v2`), which shares the file into a channel or thread and needs the `files:write` scope. An image block with `image_url` was rejected: Slack fetches the URL itself, and homelab graphs are not public. The free plan hides files older than 90 days, which is why copies are kept elsewhere.

**The agent hands an image over with a harness script, `share.py`.** It checks the file and copies it to a spool in the harness state; the gateway recognises the call (as it recognises `incident.py open`), loads the image from the spool and uploads it. Considered instead: an in-process MCP tool the gateway registers with the Agent SDK (a cleaner call, but Claude Code only; Pi would need its own extension), and uploading any image path the agent names in a reply (implicit, and a prompt injection away from posting the wrong file). The script works the same under both drivers, because both report a Bash call and its output.

**It runs without approval, so it checks what it takes.** The file must be a PNG, JPEG, GIF or WebP by its first bytes, whatever its name; SVG is refused (it is a document that can carry text and links, and Slack shows it as a file, not an image). It must be under `chat.images.max_mb` (default 5 MB). Its path, as given and with links followed, must not match the chat policy's deny paths or the harness state. There is no directory restriction: an image the agent rendered anywhere it may write can be shared. A per-share approval was considered and rejected as a click for every graph.

**The gateway trusts the spool, not the output.** The output names only a sha256. The image must be in the spool, be the type its description records, and still hash to its name; anything else posts nothing. The gateway posts only to the conversation whose agent ran the call, so a session cannot send an image into another incident. The caption is the agent's text: it is scrubbed like every post, escaped in Slack and put in code on the tracking issue, so it cannot mention or link.

**Images are not redacted.** Text redaction is pattern matching on text; an image has none to match. The control is upstream: the agent can share only images it can read, the deny-list keeps credentials out of reach, and it is told never to post an image of a secret. A graph's labels (host names, job names) are visible to the channel, as they already are in text.

**What is kept.** Copies are made only after the upload succeeds. For an incident: the harness state (`images/<incident>/<sha256>.<type>`), which `audit.py commit` puts beside the audit log as `<id>.images/` on the same branch and pull request, so the record holds exactly what people were shown; and `<evidence_dir>/<incident>/shared-<sha>.<type>`, where the review already collects evidence. The tracking issue gets one line (caption, type, size, digest prefix, link to the file in Slack), never the image: the issue is the widest-audience record, as with attachments (ADR 0023). For a question: a copy beside its log, pruned with it after 30 days, and a `shared` record in the log. Before a record exists the image is posted and not kept. `incident.py gc` removes an incident's copies with the rest of its state once its log is preserved.

**The agent can draw, read-only, with `chart.py`.** Allow-listed in every policy. `chart.py prom` runs a PromQL range query against the site's metrics backend (`slo.url`, with the same token, auth and no-redirect rule as `slo.py`), capped at 7 days and 20 series, and draws a line chart in the site's time zone. `chart.py nagios` fetches the nagiosgraph PNG through the status page's signed graph proxy: an HMAC-SHA256 over `host|service|period|timet|expires`, signed in the script with a key from `~/.config/sre-harness/<key_file>` (a regular, owner-only file the chat policy denies to the agent's own reads, as `slo.py`'s token file), with a five-minute expiry, and the "No data available" placeholder (23 pixels tall) reported as no data, exit 3. The runner's Nagios login was not used: the gateway strips it from the agent's environment on purpose. Output must be a `.png` under the evidence directory or the system temp directory. Drawing and posting are separate calls so the agent looks at the image before anyone else does. sar graphs stay with `sargraph` (the site's procedure); a PNG from it can be shared.

**Not verified against Slack before merging.** The upload call and its refusals are tested against a recording client. The first deployment should run one drill: draw, read, share in a thread, and check the incident channel, the issue line, the evidence copy and, after close-out, the audit branch.
