# Mutation detection judges each simple command by its program, and approvals pair on words

`audit.py verify` lists mutations that ran without an approval. Replaying one real incident's log gave 33 such entries for an incident with 10 recorded approvals (claude-plugins#32), and the few that mattered were lost among them. The detector matched broad patterns anywhere in a command's text, treated a multi-line command as one command, gave up on any `$(...)`, read heredoc bodies as commands, and paired an approval with a command only when the two strings were identical. This records how it works now.

**A command line is split into simple commands, and each is judged by its program.** Newlines separate commands, as do unquoted operators. Comments and heredoc bodies are taken out first, and so are substitutions, which are judged as commands of their own. Leading assignments (`C1='kubectl ... patch ...'`), shell keywords and wrappers (`sudo`, `timeout`, `env`, `nohup`) are removed, and the program word that is left decides. A rule names that program and, for programs such as `kubectl` or `systemctl`, the verbs that make it a mutation, matched as whole words. So `oom-kill` in a branch name or `mount` in a sentence no longer counts. `dd` needs `of=`, and `mount` with options alone only lists.

**Carriers are opened, not trusted or ignored.** ssh's remote command, `sh -c`, `su -c`, `watch`, `xargs`, `find -exec`, `docker exec` and `kubectl exec` run a command they are given, and that command is judged the same way. A heredoc is data unless it feeds a shell or ssh with no remote command. Any other argument holding whitespace or shell syntax is parsed again too, because a program may run it. Prose starts with an ordinary word and is not a mutation, while `--do 'rm -rf x'` still is. An argument that does not parse is matched only where a command could start in it. We considered ignoring the arguments of programs that are not carriers. That would have missed an unknown script that runs its argument, which the existing tests rule out on purpose.

**It still fails closed.** A command line longer than 20,000 characters is a mutation. A line that does not parse at all (in practice, one shortened or unbalanced by redaction) is matched by its whole text with the old patterns, as before. The only harness calls exempt are those that name the script by an absolute path. A relative `uv run scripts/timeline.py` is judged like any other program, and its prose arguments now pass anyway.

**Approvals pair per simple command, on words.** The executed side is the shell's argv. An approval's `--command` matches if its shell words, its whitespace-split words, or the `argv` stored on new records equal that argv. That covers an approval written `-p {"a":1}` for a command run as `-p '{"a":1}'`. The words must be identical, so an extra flag is a different command and stays listed: an allow-list of harmless flags would need maintaining and would give a mutation somewhere to hide. An approval of a whole command line still covers all of it.

**An approval recorded in the same call counts if it comes first.** The hook writes a call's attempt before it runs. So an approval that `audit.py record` writes from inside the call lands after that attempt and before the call's completion. Within one call, each `audit.py record --kind approval` segment takes the approval written in that window: the one naming its literal command, or the next in order when the command came from a variable. It credits only the simple commands after it. A call that never completed has no window. An approval the call did not use stands for later calls.

Decided in claude-plugins#32. Implemented in `scripts/shell_mutations.py` and `audit.unauthorised_mutations`.
