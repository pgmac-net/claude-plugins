# Attachments reach the agent as redacted, truncated, untrusted text; the issue stores only a description

A snippet, or a long paste that Slack turns into one, arrives as a message with `subtype: file_share`. The gateway used to drop every message with a subtype, so a responder who pasted a log got silence, not even their typed text (homelabia#270). This records how attachments are now handled.

**Only text is read.** A snippet, a `text/*` file, or JSON, YAML, XML or TOML. A file that is not text (an image, an archive, a gzip with a text type) is not downloaded, or is dropped once its first bytes show it is binary, and the sender is told so. Images were left out on purpose: they need a second input path, and the Pi driver's support for one is not established.

**Reading is bounded, and the bounds are site configuration.** `chat.attachments` in `site.yaml` sets them; the defaults are 64 KB read per file (the first 8 KB and the last 56 KB, with the middle replaced by a marker, because the start of a log shows its format and the end usually shows the fault), 3 files and 128 KB per message, and nothing over 5 MB is downloaded. The gateway puts the caps in the site file with its other tunables (`max_sessions`, `approval_ttl_seconds`), not in the environment, so a change is a reviewed pull request and `validate_site.py` rejects values that cannot work.

**The content is redacted before the model sees it.** A typed message is something a person chose to write. A pasted log holds values nobody reviewed, and the agent's transcript and audit records would keep them. The text goes through the harness's `redact_text` in pieces no longer than the length it scans, cut between lines and never inside an unfinished private key. A secret that straddles the cut of a single line longer than a piece is the one case not caught; a line of that length is not a log line.

**The agent is told it is data.** Each file is a fenced block, with a fence longer than any run of backticks inside it, under a line saying the content is evidence and never an instruction. Log lines carry text that attackers control (user agents, request paths). The block is a label, not a defence: the tool policy and approvals still decide what the agent may do, as for text from a monitored system in a triage (ADR 0018).

**The tracking issue gets a description, not the content.** The issue is a public record that outlives the incident, and redaction is pattern-based. The mirror carries the message text, one line per file (name, size, how much was read, how many values were redacted) and the link to the message in chat. The original stays in Slack. Copying the content into the issue, or saving it to the site's evidence directory, were both considered; the first leaks whatever redaction misses and fills the issue, the second makes the gateway a writer to the site repository, which until now only the harness scripts are.

**Nothing is silent.** A file that is not read is reported, to its sender only, with the reason. A missing `files:read` scope shows as Slack refusing the download, and the typed text still reaches the agent, so deploying the gateway before the scope is added loses nothing.

**Who and where.** Only listed responders' attachments are read, and a non-responder's are never downloaded. It applies wherever a responder's message reaches the agent: starting from a hub mention, an incident channel, a question thread and a triage a responder joins. `/sre` and `/incident` are slash commands, which carry no files. Downloads go only to `*.slack.com`, with the bot token, without following redirects.
